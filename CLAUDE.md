# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Общее

PWA-метроном для музыкантов. v2 — полная перестройка с нуля (2026-09-27,
см. `../metronom-v2-plan.md` для истории решений). TypeScript + Vite,
**без React, без Tailwind**, без собственного сервера. Вход — через Google
(Firebase Auth), данные и живая синхронизация — Firebase Firestore, всё в
аккаунте пользователя. Статика деплоится на тот же домен
Hostinger, что и раньше.

Если ищете описание архитектуры v1 (React + Express + MySQL) — она удалена
целиком, см. `git log` до коммита `v2 reset` и `../metronom-v2-plan.md`.

## Архитектура кода

### Экраны и роутинг

Без React → без React Router. `router.ts` — самописный: путь → функция
рендера (`history.pushState`, паттерны `/song/:id`). `app.ts` — единственное
место, где роутер связывается с экранами; держит один `AudioEngine` на всё
приложение и общий хедер/футер (`components/appHeader.ts`,
`components/appFooter.ts`).

Маршруты: `/metronome`, `/playlist`, `/song/:id`, `/song/:id/pattern`,
`/settings`, `/beats`, `/beats/:id`. Всё остальное (включая `/`) редиректит
на `/metronome`. Футер: Метроном · Плейлист · ▶ · Биты · Настройки
(кнопки метронома раньше не было — с других экранов к кольцу было не
вернуться).

`appHeader.ts` — назад/отмена всегда слева (иконка), заголовок, справа
кнопки страницы (`actions`): замок и дискета — маршрут включает их в
`setScreen(..., { lock, save })` (см. «Замок и дискета» ниже). Экран не может напрямую подёргать чужую иконку в шапке
(шапка — в `app.ts`, экран монтируется отдельно): маршрут в `app.ts` держит
`let requestX`, передаёт `(fn) => { requestX = fn }` экрану третьим/четвёртым
параметром, экран при монтировании один раз кладёт туда свою функцию —
см. `/beats/:id` + `beatEditorScreen.ts` (`onRegisterSave`) как образец, если
понадобится ещё одна кнопка в шапке у другого экрана.

### Замок и дискета (защита от случайных правок)

Решение пользователя. **Замок** (`components/lockButton.ts`, справа в
шапке) — на «Плейлисте», в песне, в «Битах» и в бите библиотеки. Закрыт —
удалять, перемещать и править нельзя: кнопки показываются неактивными
(корзины, −/+, карандаши, «Добавить секцию», сетка бита), значения (темп,
размер, кит, квадратики долей) видны, но не нажимаются. Играть, открывать,
смотреть, добавлять новое (песню, плейлист, «Создать» бит) и переключать
плейлисты можно. Открывается долгим тапом (600ms), закрывается обычным;
свой у каждой страницы — при входе на страницу снова закрыт
(`state.unlocked`, `resetPageEditing()` в `enterPage`). Шапка
пересобирается, как только замок открылся, — click отпускания того же
пальца приходит новой кнопке и пропускается (`swallowClick`).

**Дискета** — песня, паттерн песни и бит библиотеки правятся
**черновиком** (`state.draft`, `setDraft`/`songView`/`beatView` в
`appState.ts`): в аккаунт — только дискетой (`commitDraft`), без неё правки
не сохраняются. Дискета неактивна, когда сохранять нечего (`draftDirty()` —
сравнение с сохранённым по `stableStringify`); у бита библиотеки дискета ещё
и переименовывает (имя → сохранить → назад), поэтому активна и с открытым
замком. У паттерна песни — только дискета, без замка (решение
пользователя). Свой паттерн метронома — как раньше, сразу в аккаунт.
Играет движок черновик (`withDraft` в `app.ts` подставляет его в песни/биты
для `engineSettingsFor`). Новые биты, созданные из песни («Редактировать»
филл, копия квадратика), уходят в библиотеку сразу — в черновике песни
только ссылка на них.

**Уход с несохранёнными правками** — окно «Сохранить / Не сохранять /
Остаться» (`components/leaveDialog.ts`, `<dialog>` в `body`, вне `#app`).
Перехватывает его `router.setGuard()` — и переходы приложения
(`navigate`: назад в шапке, футер, ссылки экранов), и «назад/вперёд»
браузера: адрес там уже сменился, роутер возвращает историю на запись
страницы через `history.go()` (номер записи — `history.state.index`), а
согласились уйти — снова туда. Закрытие вкладки — `beforeunload`, окно
браузера. Ответ окна — по нажатию, не по событию `close`: в фоновой вкладке
Chrome его не шлёт, окно «залипало».

**DOM-структура — строго `#app (div) > div.app-header, div.screen, div.app-footer`**
(ровно три div-а, без лишней вложенности; никаких `<header>`/`<main>`/`<footer>`
— осознанное требование, не рефакторить обратно на семантические теги).
`#app` растягивается на весь экран устройства (`100dvh`, см. `tokens.css`) и
является flex-колонкой; `.app-header`/`.app-footer` — обычные flex-дети
(`flex-shrink: 0`, НЕ `position: fixed` — так было раньше, отказались),
`.screen` — `flex: 1; overflow-y: auto` и сам скроллит контент, если он не
помещается, а хедер/футер остаются на месте. `app.ts` хранит `headerEl`/
`footerEl` как переменные и на каждый рендер шапки/футера подменяет их
целиком через `replaceWith(...)` (не через mount-в-пустую-обёртку) — так
структура остаётся "три div-а — прямые дети `#app`", а не "div, содержащий
div".

### Состояние

`state/appState.ts` — простой pub/sub (не Redux, не фреймворк): один объект
`AppState`, `subscribe(cb)` на изменения, `patchState()`/`saveSongs()` и
т.д. на запись. Экраны сами решают, что перерисовывать при уведомлении —
никакой виртуальный DOM ничего не диффит за них.

**У каждой страницы свой звук и свои настройки — друг на друга они не
влияют** (решение пользователя):
- «Метроном» — `state.metronome` (`setMetronome`): темп, размер, «Считать
  вслух»; запоминается в localStorage, от песен и битов не зависит.
- Песня — песня со своими `bpm`/`beatsPerBar`/`beatDivision` (строка темпа
  наверху экрана песни, пишется в песню).
- Редактор паттерна песни (`/song/:id/pattern`) — только паттерн, по кругу,
  в темпе песни (источник `songPattern`).
- Редактор бита — бит со своим `Beat.bpm` (пишется в бит; новому из
  «Редактировать» на доле — темп песни).
- Списки и настройки — без звука: Play там неактивен (если ничего не
  играет), а уже играющее доигрывает.

Перешли на страницу с другим звуком — игра останавливается (песня → её
паттерн — тоже: там играет только паттерн). Источник звука страницы —
`PlaybackSource`, `enterPage()` в `app.ts`; что и как играть —
`engineSettingsFor()` (`data/engineSettings.ts`).

**BPM метронома — скорость каждой точки кольца** (крупной и мелкой): 120 —
удар раз в 0,5 с, круг 4/4 из 16 точек — 8 с. Движку уходит BPM доли —
`bpm / beatDivision`. **В песнях и битах BPM — доля** (крупная точка), как
принято в нотах (решение пользователя).

**Горячий путь — исключение из этого правила.** Подсветка текущей доли
(`screens/metronomeScreen.ts`), играющего шага в редакторе бита
(`screens/beatEditorScreen.ts`) и сетки долей секций песни
(`screens/songScreen.ts`) обновляются НАПРЯМУЮ в DOM из
`engine.onPlaybackState(...)`, в обход `appState`/перерисовки экрана —
иначе на 24 кадрах в секунду есть риск, что рендер собьёт аудио-тайминг
(тот же принцип, что был в v1 с React, просто без React в середине). Слот у
движка один; `onPlaybackState` возвращает отписку — экран вызывает её при
уходе (снимает слот, только если он всё ещё его).

### Построение DOM

Без фреймворка — `dom.ts` даёт `h(tag, props, ...children)` (тонкая
обёртка над `document.createElement`, не виртуальный DOM) и `mount()`
(заменить детей контейнера). Экраны и компоненты используют только это,
не пишут `document.createElement` россыпью.

**Экраны перерисовываются целиком на любое изменение состояния — в том
числе посреди ввода** (снимок Firestore, загрузка сэмплов). Поэтому:
- `mount()` возвращает фокус, курсор и прокрутку элементам с ключом:
  `h('input', { key: '...' })` → `data-key`. Поле ввода и прокручиваемая
  лента без ключа теряют фокус/прокрутку на каждую перерисовку (форма секции
  раньше закрывала клавиатуру после каждой буквы, сетка паттерна — уезжала
  к первому шагу на каждый тап).
- Ввод держать в черновике (переменная экрана), а не перерисовывать экран на
  каждую букву: форма секции (`songScreen.ts`) правит черновик без
  `render()`.
- Применение ввода по `blur` — только `if (!isRemounting())`: Chrome шлёт
  `blur` полю, которое уходит из DOM или переезжает, синхронно и ещё до
  удаления (`isConnected` там ещё `true`) — недописанное «14» на пути к
  «140» применялось бы. Не переносить узел с полем в фокусе вне `mount()`:
  кольцо метронома лежит в постоянном каркасе экрана, а не пересобирается.
- Числовые поля — `type="text"` + `inputmode="numeric"` + `keepDigits()`, не
  `type="number"`: у number браузер не отдаёт позицию курсора, и после
  перерисовки курсор вставал в начало («14» + «0» = «014»).

### Дизайн-система

`design/tokens.css` — единственный источник цвета/отступов/радиусов/
типографики, CSS custom properties. Тема переключается атрибутом
`data-theme` на `<html>` (`state/appState.ts` → `setThemeId`). Сейчас одна
тема (Minimal) — добавление второй (`light`/`dark`) означает **только**
новый блок `[data-theme="..."]` в `tokens.css`, компоненты не трогаются
(так и задумано, см. `metronom-v2-plan.md`).

`design/components.css` — каталог переиспользуемых классов (`.btn`,
`.icon-btn`, `.card`, `.input`, `.list-row`, `.step`, `.badge`, `.banner`,
`.app-header`, `.app-footer` и т.д., список — в начале файла) плюс
раскладка и текст (`.stack`, `.row`, `.grow`, `.text-sub`, `.text-small`,
...). **Правило**: перед новым экраном — искать подходящий класс здесь,
использовать его, а не писать инлайн-стиль. Инлайн — только данные:
координаты и CSS-переменные из кода (`--cell-color`, `--pattern-steps`,
позиции точек кольца). Новый переиспользуемый элемент — сюда же, в
комментарий-список в начале файла.

Иконки — шрифт Phosphor из npm (`main.ts`), не с CDN: так Service Worker
прекеширует их (`woff2` в `globPatterns`), и офлайн кнопки-иконки не
пустеют. Барабана в Phosphor нет (`ph-drum` не существует) — `icon('drum')`
рисует SVG малого барабана из `drumIcons.ts`. Новую иконку — сверить, что
она есть в `node_modules/@phosphor-icons/web/src/bold/style.css`.

**Частый источник бага** (уже наступали): у модификатора (`.btn--accent`,
`.icon-btn--danger` и т.д.) и у `:hover`/`:active` на базовом классе
(`.btn:hover`) одинаковая специфичность CSS (один класс = один класс+один
псевдокласс на самом деле ВЫШЕ — `.icon-btn:hover` специфичнее
`.icon-btn--accent`!). Если у модификатора нет своего `:hover`-переопределения,
дефолтный hover-фон побеждает акцентный цвет, и светлая иконка становится
не видна на светлом фоне. Добавляя новый цветной вариант кнопки — сразу
добавить и его `:hover`.

### Аудио-движок

`engine/audioEngine.ts` + `engine/sampleLoader.ts` — тот же алгоритм, что
был в v1: `setTimeout` каждые 25ms планирует ноты на 100ms вперёд через
`AudioContext.currentTime`; события для UI кладутся в очередь и
применяются отдельным `requestAnimationFrame`-циклом. Фабричные функции с
замыканиями вместо React-хука (`createAudioEngine()`), `{ current }`-объект
вместо `useRef`, колбэки (`onPlaybackState`, `onPlayingChange`, ...) вместо
`useState`.

Один `AudioContext` на всё приложение — создаётся один раз через
`ensureAudioContext()` внутри `audioEngine.ts` (при создании движка, чтобы
декодирование сэмплов не зависело от того, выбрана ли песня — см. ниже) и
переиспользуется и для декодирования, и для воспроизведения. Не создавать
второй через `new AudioContext()` в другом месте — сэмплы, декодированные
через один контекст, всё ещё должны воспроизводиться, но плодить лишние
контексты незачем.

**Изменение BPM во время игры** применяется без остановки/перезапуска —
естественное следствие того, что `schedule()` читает `bpm` из замыкания на
каждой итерации, а не из захваченных при последнем вызове параметров (в
v1 с `useCallback` это было не так, BPM обновлялся только после
стоп/старта). Не буквально мгновенно — уже запланированная на старом
темпе доля довисит, новый темп стартует со следующей. См.
`tests/audioEngine.test.ts`.

**samplesLoaded не завязан на выбор песни.** В v1 `preloadAllSamples()`
запускался только при выборе песни — значит голый метроном без песни был
неиграбелен (кнопка Play заблокирована до `samplesLoaded`). В v2 движок
декодирует все сэмплы сразу при создании (`createAudioEngine()`), не
дожидаясь песни — метроном первая фича по плану, должна работать без неё.
А простой щелчок их и вовсе не ждёт (`canStart`, см. выше); не
загрузившиеся сэмплы (не было сети) пробуются заново на каждом Play.
Повторно при `setSong()` сэмплы не грузятся — раньше это на каждую правку
песни/бита давало лишний `patchState` и перерисовку всего.

**Гейн у синтезированного звука — обязательно `setValueAtTime(v, time)`,
не `gain.gain.value = v`** — и у щелчка, и у запасного осциллятора вместо
незагрузившегося сэмпла (там было `.value` — тот же баг, исправлено). Клик (см. ниже) планируется на будущее время
через lookahead (до 100ms вперёд в `schedule()`). Если задать `.value`
напрямую, автоматизация стартует от «сейчас», а не от `time` — к моменту
реального `start(time)` экспоненциальный спад уже почти долетел до нуля,
и звук получается не слышен. Один раз уже наступали на это в `clickSound()`.

**Сетка долей секции песни** (`screens/songScreen.ts`, `.bar-grid`) —
возвращена из v1 (`SectionCard.tsx`): в каждой карточке секции квадратик на
долю (`bars × beatsPerBar`, доли — из размера песни, в строке — целые такты, до
8 квадратиков), первая доля такта отмечена. Во время игры прошедшие доли
закрашены, текущая выделена, карточка текущей секции — `.card--active`, и
экран доезжает до неё (`scrollIntoView`). Номер доли считается от начала
песни (`bar × beatsPerBar + beat − 1`), как в движке.

**Источник звука — на каждую долю** (`soundSourceAt()` в `audioEngine.ts`):
филл секции, покрывающий эту долю (поздний перекрывает ранний, обрезается
концом секции) → бит секции (по кругу от начала секции) → паттерн песни
(по кругу от начала песни). **Бит или филл секции без единой ноты — пауза**
(решение пользователя: так делается брейк-«стоп»); пустой паттерн песни —
как и раньше, щелчок. Шагов на долю — `Pattern.stepsPerBeat` (у бита
— M его размера N/M; паттерн песни — тоже бит). `patternStep` в
событиях — только для паттерна песни (его подсвечивает
плейхед редактора бита), для бита/филла секции `-1`. Тест — последние в
`tests/audioEngine.test.ts`.

**Движок догоняет состояние в `app.ts` (`syncEngine`, подписчик
состояния)** для источника звука текущей (или последней со звуком)
страницы: темп, голос, размер и что играть (`engineSettingsFor`,
`songForEngine`): метроном — щелчок/голос, песня — копия с подставленными
паттернами битов секций (`resolveSongForEngine()`), бит — паттерн бита без
секций. Пересобирается при изменении и песни, и битов (правка бита в
«Битах» сразу слышна в песне); каждое сохранение — новый объект, поэтому
«изменилась» = другая ссылка. Экраны меняют только состояние, движок не
трогают (кроме Play/Stop и прослушки). `syncEngine` не вызывает
`patchState` — рекурсии нет. Подписан раньше футера и экранов: футер
смотрит `engine.canStart`, кольцо — размер движка. Песню или бит удалили,
пока играли, — игра останавливается.

**Play** (`engine.canStart`): простому щелчку сэмплы не нужны (он
синтезируется) — Play доступен сразу; паттернам и голосу нужны — ждём
загрузки. Повторный `start()`, пока движок запускается (`await
ctx.resume()`) или играет, ничего не делает; `schedule()` и цикл отрисовки
помнят номер своего запуска (`runId`) и выходят после `stop()` — двойной тап
раньше запускал второй планировщик, который не глушился Стопом.

**Стоп глушит звук сразу** (`silenceScheduled`): звуки отдаются звуковой
карте наперёд — lookahead, а удары внутри доли сразу на всю долю (у
метронома при 120 и 4/4 доля — 2 с). Движок помнит запланированные
источники (`track`) и по `stop()` останавливает и отключает их — раньше
после Стоп доигрывали до 3 ударов. Прослушка (`previewSound`) не
отслеживается.

**Конец такта — `beat >= beatsPerBar`, не `===`**: долей могли убавить во
время игры, когда счёт уже за новым концом такта, — с `===` доля росла без
конца, такт и секции стояли.

**Опоздавшая доля пропускается, а не играется** (`LATE_SKIP_SEC`): вкладку
придушили, планировщик проснулся, когда доли уже прошли, — без этого они
прозвучали бы разом пачкой. Счёт тактов при этом идёт — песня в своём
времени.

Экраны на сброс позиции смотрят на `engine.isPlaying`, поэтому движок при
остановке (и ручной, и по концу песни) сначала ставит `isPlaying = false`,
потом сбрасывает позицию. По концу песни раньше было наоборот — экраны
принимали сброс за «играет, такт 0, доля 1» и оставляли подсветку.

### Кольцо метронома (dial)

`components/beatRing.ts` + `.dial`/`.dial__dot*` в `design/components.css`.
Термины (несколько раз путались раньше — не путать при правках):
- Весь круг целиком — один такт.
- Крупные точки (`--large`) — доли такта, `beatsPerBar` (12/3/6/9 часов
  при 4 долях).
- Мелкие точки (`--small`) — деление доли, `beatDivision`: сколько ударов
  умещается в одну долю, точки лежат МЕЖДУ соседними крупными.
- Размер и темп — метронома (`state.metronome`, запоминаются), песни на
  них не влияют. Правятся бейджем «N/M» и числом в центре кольца
  (`components/tempoControls.ts` — те же элементы, что в строке темпа песни).
- **Каждая точка — удар в темпе BPM** (не доля!): точка вспыхивает и
  звучит. Щелчок — акцент на крупной, обычный на мелкой. «Считать вслух» —
  на каждой точке: крупная — номер доли, мелкие — номер внутри доли (one,
  two, three, four, two, two, three, four, three, …), без доп. акцента
  (решение пользователя); голосов — до восьми.
- Размер «4/4» = `beatsPerBar=4, beatDivision=4` — это ровно тот случай,
  когда клик, мигание и (при «Считать вслух») счёт совпадают на каждой
  точке круга, крупной и мелкой одинаково.

«Включить мигание» (`state.metronome.flash`, по умолчанию выкл.): выключено —
кольцо не вспыхивает, а по точкам прыжками ходит стрелка (`.dial__hand`,
`ring.setHandMode`), за ней прыжками растёт тёмный полупрозрачный сектор от
12 часов (`.dial__sector`, `conic-gradient`, сброс в начале такта); точки
закрашиваются как обычно; стоим — стрелка на 12, сектора нет.

«Свой паттерн» (решение пользователя): галочка `metronome.usePattern`
(настройка устройства) — играть паттерн вместо щелчка; карандаш — тот же
редактор бита (`/metronome/pattern`, `metronomePatternTarget`: темп —
метронома, имени и дискеты нет, «Загрузить из моих битов» — копия бита из
библиотеки). Сам паттерн — в аккаунте, поле `metronomePattern` документа
`users/{uid}` (`saveMetronomePattern`, с дебаунсом). С паттерном метроном
остаётся собой — скорость, размер, кольцо, мигание/стрелка его; звучит
только паттерн, по кругу своей длины. **Доля паттерна = доля метронома**:
паттерн N/M занимает N долей, его M клеток делят долю (2/3 на 4/4 — триоли
на две доли). Бейдж размера при этом неактивен (`.dial__meter--fixed`,
решение пользователя). Шаги паттерна внутри доли — события `step` движка:
меняют только `patternStep`, точку кольца не трогают (иначе кольцо
откатывалось бы на крупную точку посреди доли); вспышка — только на точку
кольца. Не вошли (паттерна нет) — щелчок. Скорость паттерна относительно
метронома — бейджи ×½ / ×1 / ×2 рядом с «Свой паттерн»
(`metronome.patternSpeed`, решение пользователя; щелчки и голос не
меняются): ×2 — вдвое больше шагов на долю, ×½ — каждая клетка растянута на
два шага (`withSpeed` в `data/engineSettings.ts`; движку нужны целые шаги
на долю). В редакторе «Свой паттерн» — та же скорость.

Раскладка экрана: кольцо — квадрат по меньшей стороне свободного места
(`.metronome__dial-area`, `container-type: size`, `.dial` — `100cqmin`, точки
в процентах), кнопки темпа и галочки — внизу над футером. У `.metronome`
именно `height: 100%`: с `min-height` Chrome не видит высоту области в
единицах `cq*`, `100cqmin` = 0 и кольцо схлопывается в точку.

Заливка кольца (`.dial--flash`) и закраска точек (`.dial__dot--filled`)
копятся весь такт и разом гаснут в начале следующего (см. `filled: Set`
в `beatRing.ts`, очищается на `beat === 1 && subBeat === 0`) — это НЕ
одна бегущая точка/вспышка, которая гаснет сама по себе.

Звук (`clickSound()` в `audioEngine.ts`) — синтезированный осциллятор, не
сэмпл: акцент на каждую долю (крупная точка), обычный клик на каждый удар
деления (мелкая точка). Раньше деление было чисто визуальным — теперь
звучит тоже, но только в режиме простого клика (не в паттерне, не при
«Считать вслух» — там на его месте, соответственно, паттерн-сэмплы или
голос).

### Библиотека битов и брейков (для барабанщика)

Страница `/beats`, `/beats/:id` — короткие кастомные паттерны (до 128
шагов), хранятся в аккаунте (`users/{uid}/beats`), назначаются в секции
песни (бит секции, филлы — см. ниже). Два ключевых архитектурных решения, которые
важно не сломать при правках:

**Роль ≠ сэмпл.** `Beat.tracks[].role` — одна из 8 фиксированных ролей
(`DRUM_ROLES` в `config.ts`: kick/snare/hihat/tom1/tom2/tom3/crash/ride), не
сэмпл напрямую. Реальный файл даёт «кит» (`DRUM_KITS`, сейчас `real` и
`pearl` — оба реально доступных кита в `public/sound/`). `data/resolveBeat.ts`
конвертирует `Beat` в обычный `Pattern`/`PatternTrack` (резолвя роль → сэмпл
через кит) прямо перед `engine.setSong(...)` — поэтому `audioEngine.ts` про
`Beat`/`DrumKit` вообще не знает и не менялся. Кит выбирается на самом бите
(`Beat.kitId`, не общая настройка приложения) через «Sound» в редакторе —
план `playful-snacking-mountain.md` в истории изначально откладывал этот
выбор в UI, добавлено следующим шагом сразу после.

**Длина бита — свободная, в шагах: `Beat.steps` (1..`BEAT_MAX_STEPS` = 128),
не в тактах** — как у референса (realdrummetronome.com/editor), решение
пользователя. Шаги добавляются/удаляются по одному («+» справа от сетки,
корзина под каждым столбцом, тап по «призрачному» столбцу за концом, копия
вправо/вставка за концом). Раньше длина хранилась целыми тактами
(`Beat.bars`) — `normalizeBeat()` (`data/beatsLibrary.ts`) пересчитывает.

**Размер бита «доли × удары» (N/M = `beatsPerBar` долей по `beatDivision`
клеток) — определяется по числу столбцов автоматически, весь бит — один
такт** (`data/beatMeter.ts`, решение пользователя): делится на 4 → N/4;
иначе на 3 → N/3; иначе N = наименьший простой множитель (простое → 1/число):
4 = 1/4, 6 = 2/3, 8 = 2/4, 10 = 2/5, 16 = 4/4, 7 = 1/7. Ударов на долю — не
больше 8 (`MAX_BEAT_DIVISION`), дальше N долей по одному удару: 11 = 11/1,
22 = 22/1, 127 = 127/1 (раньше 127 ударов звучали за одну долю). Кратные 12
неоднозначны (12 = 3/4 или 4/3) — только тогда над сеткой переключатель
(`.dial__meter--active`), выбор держится, пока длина допускает его.
Пересчёт — в `onEdit` редактора на каждое изменение длины. Темп бита —
`Beat.bpm`, свой у каждого (доли в минуту, как в песне); в песне бит
играет в темпе песни. **Шаг бита
звучит как 1/M доли** (`Pattern.stepsPerBeat = beatDivision`), бит на N/M
в песне занимает ровно N долей. Номеров тактов в сетке нет (бит = такт),
линия отмечает конец бита. `Pattern.steps` в `resolveBeat.ts` = `beat.steps`, не
«такты × 16» (один раз уже разошлось и играло не в такт).

**Бит играет ровно `beat.steps` шагов по кругу — поэтому в движок он уходит
БЕЗ секций** (`sections: []` в `songForEngine()`, `data/engineSettings.ts`). С секцией движок
обрывал круг на конце «песни», считанной в СВОИХ тактах (доли × 2 шага,
например 8): 7 шагов играли как `0123456 0123456 01 | 0123456…`. Не
возвращать туда секцию; тест — последний в `tests/audioEngine.test.ts`.

**Биты и филлы в секциях песни.** `Section.beatId` — бит из библиотеки как
грув на всю секцию вместо паттерна песни (выбор «Бит секции» в форме
секции). `Section.fills: { at, beatId }[]` — филл с доли `at` (от начала
секции, с 0): тап по квадратику-доле в сетке секции (`songScreen.ts`) →
меню из кнопок (решение пользователя): «Редактировать», «Из списка»
(список битов — вставить филл с этой доли), «Копировать влево/вправо»
(квадратик целиком в соседний — `squareContent()` в `data/songs.ts`: филл
на долю — он сам, кусок филла/грува/паттерна — новый бит на долю, щелчок —
у соседа снимается филл; на крайнем квадратике кнопка неактивна, меню
переезжает на копию), ×. «Убрать филл» нет — филл только заменяют. Доли
под филлом — `.bar-grid__cell--fill`; текстом («Филл … с доли N») филлы в
карточке не подписываются (решение пользователя). В песне только
ссылки; `groove`/`fillPatterns` в `Section` — поля копии для движка
(`resolveSongForEngine`), в БД не пишутся. «Редактировать» в выборе филла
(`editAt` в `songScreen.ts`) правит то, что звучит в этом квадратике, и
только здесь — всегда через новый бит-филл на этой доле: копия стоящего
филла / кусок грува секции или паттерна песни на одну долю / пустой 1/4
при щелчке (пустой филл — пауза); редактор открывается из песни и «назад»
возвращает к той же секции (`beatEditorReturn`/`songFocus` в `app.ts`, по
id секции). Расчёт куска — `sliceForBeat()` в `data/songs.ts`, по тем же
правилам, что у движка. Удалённый бит — «бит удалён», секция играет паттерн
песни. Биты из «Создать» и «Редактировать» сохраняются сразу; удаление —
красная корзина в строке списка «Биты» с подтверждением
(`components/deletableRow.ts`, тот же компонент — у песен в списке
плейлиста). Общий доступ к битам — отложен.

**Редактор бита — один на весь сервис** (решение пользователя):
`mountBeatEditorScreen(container, target, …)` правит то, что даёт
`BeatEditorTarget` — бит библиотеки (`libraryBeatTarget`: свой темп,
название через дискету «Сохранить», замок) или паттерн песни (`songPatternTarget`:
темп — песни, имени нет, дискета без замка), или свой паттерн метронома. Своего редактора у паттерна песни больше
нет: **паттерн песни — бит внутри песни** (`Song.pattern: Beat`, не в
библиотеке «Биты»), играет в секциях без своего бита по кругу от начала
песни; движку — разрешённый в сэмплы (`EngineSong.pattern`,
`resolveSongForEngine`). Старый формат паттерна (16 восьмых, дорожки
bd/sd/hh) при чтении выкидывается — песня начинает с пустого
(`normalizeSongPattern`, решение пользователя: не переносить). Удаление
песни — только корзиной в списке плейлиста.

**▶ на секции — играть с неё** (решение пользователя): кнопка ▶ на
карточке каждой секции, кроме вводной; перед секцией 2 такта отсчёта в
размере и темпе песни — голос номера доли (до восьми) + акцентный щелчок на
каждую долю, без голоса смены секции; потом песня с этой секции до конца.
Уже играет — перезапуск с выбранной. `engine.start({ fromBar, countInBars })`:
такты отсчёта идут до `countInEndBar`, для экранов у них такт −1 (сетка
песни не подсвечивается); пройдя, отсчёт сбрасывается — зацикленная песня
не отсчитывает на каждом круге. Play в футере — с начала, без отсчёта.

**Секции — по id (`Section.id`), не по индексу** (`songScreen.ts`): индексы
сдвигаются при удалении, перетаскивании и правке с другого устройства —
открытая форма правки иначе сохранялась в соседнюю секцию. Секциям без id
(сохранены раньше) `normalizeSong()` даёт `s0`, `s1`, … по позиции —
одинаково на всех устройствах до первой записи. Такты секции — целое
1..32 (`clampBars`, `CONFIG.MAX_SECTION_BARS`, решение пользователя).

**Сетка — `components/beatGrid.ts`, копия сетки референса и её поведения**
(изучено вживую и по их JS-бандлу): строки — SVG-иконки ролей
(`components/drumIcons.ts`, тап — прослушать через `engine.previewSound()`),
«+» под ними — добавить строку, корзина в конце строки — удалить; лента
столбцов 44×32px с горизонтальной прокруткой. Выделение — прямоугольник
(строки × шаги): мышью протянуть, на тачскрине подержать 350ms и вести
(просто провести — прокрутка). Тулбар над выделением: копировать / копия
влево / копия вправо (перезаписывают вплотную, выделение едет на копию) /
залить строки (повтор по всей длине с сохранением фазы) / отмена; Esc, ⌘C,
Enter. Вставка — полупрозрачный блок за курсором на любые строки, клик
(на тачскрине — кнопка в тулбаре), повторно до отмены, красная рамка — не
влезает по высоте. Подсветка играющего шага — напрямую в DOM
(`grid.setPlayhead`). Включённая нота всегда сразу звучит — у референса
это переключатель «Play sound on cell click», у нас он убран, всегда вкл.

Сетка — **один живой элемент на весь экран**: `beatEditorScreen.ts`
перерисовывает только блоки над/под ней, а ей отдаёт свежий бит через
`grid.update()`. Не возвращать её в общий `mount()` экрана — на каждый тап
терялись бы прокрутка ленты и захват указателя посреди выделения. Правки
сетка не сохраняет сама — отдаёт `{ steps, tracks }` через `onEdit`.


### Данные и синхронизация (Firebase: вход через Google + Firestore)

**Всё — в аккаунте пользователя.** Вход через Google (`data/auth.ts`,
`signInWithPopup`), Firebase помнит его между запусками. Без входа экраны
плейлиста и битов показывают карточку входа (`components/signInCard.ts`,
`accountGate()`), метроном работает и без входа. Коды плейлистов, общий
доступ группы и передача битов по коду **убраны и отложены** — решение
пользователя, к ним вернёмся отдельной задачей.

Firestore (`data/userLibrary.ts`):
- `users/{uid}` → `{ lastPlaylistId, metronomePattern }` — свой паттерн
  метронома; последний плейлист открывается сам
  один раз при входе (`appState.applyCurrentPlaylist`, флаг `autoOpenDone`).
- `users/{uid}/playlists/{id}` → `{ name, createdAt, updatedAt, songsMigrated }`.
- `users/{uid}/playlists/{id}/songs/{songId}` → `Song` + `updatedAt` —
  песня отдельным документом (решение пользователя): конфликт
  last-write-wins — на одну песню, а не на весь плейлист.
- `users/{uid}/beats/{id}` → `Beat` + `updatedAt`.

**Перенос старых плейлистов** (`migrateLegacy`): раньше песни лежали
массивом в поле `songs` документа плейлиста. Без `songsMigrated` плейлист
работает по-старому (читает и пишет массив), а при снимке с сервера
транзакция раскладывает массив по документам и ставит `songsMigrated`;
массив остаётся нетронутым — резервная копия. Офлайн транзакция не проходит
(не ошибка) — повторится со следующим снимком с сервера. Плейлист с
неотправленной правкой массива не переносится, пока она не дошла (иначе
правка осталась бы только в копии). Устройство со старой версией
приложения (до обновления Service Worker) пишет в массив — после переноса
эти правки не видны; обновится при следующем открытии.

Песни и биты — через `data/docSync.ts`: подписка `onSnapshot` + запись с
дебаунсом `CONFIG.SAVE_DEBOUNCE_MS` на каждый документ. `save(весь список)`
сам находит изменённые (по содержимому — `stableStringify`, не только по
ссылке), новые и удалённые. Пока у документа идёт таймер дебаунса, снимок
его версию не берёт (держит локальную) — иначе снимок от соседней записи
откатывал бы только что сделанные тапы. До первого снимка запись ждёт
(иначе удалили бы то, чего ещё не видели). Правка песен до первого снимка
плейлистов (сразу после «Повторить») ждёт в `queuedSongs`. Перед выходом из
аккаунта — `flush()` (после `signOut` прав на запись уже нет):
`appState.signOut()`.

**Ошибка синхронизации** (`onSnapshot` после ошибки сам не оживает) —
плашка `.banner` над футером с причиной и «Повторить»
(`appState.retrySync()`: библиотека открывается заново, открытый плейлист и
песня не сбрасываются).

`firebase.ts`: Firestore с `persistentLocalCache` (PWA работает офлайн на
кэше) и `ignoreUndefinedProperties` (необязательные поля моделей бывают
`undefined` — без этого Firestore отказывается писать документ).

**Правила Firestore** — действуют опубликованные в консоли; копия —
`firestore.rules` в корне (правите — опубликуйте в консоли):
```
match /users/{uid}/{document=**} {
  allow read, write: if request.auth != null && request.auth.uid == uid;
}
```
В консоли также: Authentication → Google включён, Authorized domains —
домен Hostinger (localhost есть по умолчанию).

**Риск — вход на iPhone из иконки на экране «Домой»**: всплывающее окно в
такой PWA может не сработать, а вход через перенаправление в Safari сломан
для сайтов не на Firebase Hosting. Если не заработает — разместить служебные
файлы входа Firebase на нашем домене (документированный Firebase способ).

**Перед первым использованием** — обязательно заполнить
`src/data/firebaseConfig.ts` данными реального Firebase-проекта (инструкция
в комментарии в файле). Без этого `getDb()` бросает понятную ошибку, а
экраны аккаунта показывают подсказку вместо падения.

### PWA / прекеш

`vite.config.ts` → `vite-plugin-pwa`, `globPatterns` держится в синхроне
со списком реально используемых сэмплов в `src/config.ts`
(`ALL_INSTRUMENTS`) — добавили новый сэмпл в код, добавьте и в
`globPatterns`, иначе он либо не прекешируется (обычно не страшно — просто
не будет работать офлайн до первой загрузки онлайн), либо, если убрали из
кода но не из `globPatterns`, сборка предупредит, что паттерн ничего не
поймал. Шрифт иконок — `woff2` в прекеше; его SVG/TTF/WOFF Vite тоже
кладёт в `dist` (на них ссылается CSS пакета), но в прекеш они не идут
(`globIgnores`, SVG-шрифт — 2.9 MB).

Зависимости: `overrides` в `package.json` поднимает `@grpc/grpc-js`
(тянется Firestore, только для Node — в браузерный бандл не попадает) —
иначе `npm audit` показывает уязвимости, а свежий Firebase их не чинит
(всё ещё 1.9.x) и добавляет ~200 kB к бандлу.

## Деплой

Один workflow (`.github/workflows/deploy.yml`): typecheck + `npm test` +
`vite build` + SCP `dist/` на тот же Hostinger-домен, что и в v1
(`slateblue-crow-206906.hostingersite.com`). Бэкенда больше нет — значит
нет pm2, нет PHP-прокси, нет отдельного серверного деплоя. Загрузка — до
3 попыток (пауза 30 с, потом 60 с, у каждой предел 10 минут): SSH Hostinger
временами обрывает подключение при зелёных сборке и тестах. `scp-action`
закреплён по коммиту (ему отдаётся SSH-ключ хостинга); SCP не удаляет
старые файлы на сервере — старые `assets/*` копятся, это безвредно.

`public/.htaccess` — SPA-fallback для самописного роутера (без него
обновление страницы на `/playlist` или `/song/:id` даст 404 от Apache
вместо `index.html`). Он же означает, что `/api/...` и вообще любой
несуществующий путь тоже вернёт `index.html` с 200 — это нормально,
проверять деплой по факту (что в `index.html`/бандле), а не по статус-коду.

**CDN Hostinger (`server: hcdn`) кэширует `.js` на неделю** — в том числе
`sw.js`, по которому PWA узнаёт о новой версии. Однажды он закэшировал
старый `sw.js` за минуту до конца деплоя, и приложение неделю оставалось
старым. Поэтому `public/.htaccess` запрещает кэш для `sw.js`,
`registerSW.js`, `index.html`, манифеста. Проверка: `curl -sI <домен>/sw.js`
— `cache-control: no-cache…`; что лежит на сервере в обход CDN —
`curl <домен>/sw.js?bust=<число>`. Застрявшую копию на CDN сбрасывает
только «Очистить кэш» CDN в hPanel.

**После любого деплоя браузер может показывать старую версию** —
PWA (`vite-plugin-pwa`, `registerType: 'autoUpdate'`) кэширует себя через
Service Worker. Смотрите не только на сервер (`curl`/содержимое
`dist/index.html`), а и на то, что реально отдаёт браузеру SW. Сброс:
DevTools → Application → Service Workers → Unregister → Cmd+Shift+R,
или просто открыть в приватном окне (это уже было граблями в v1).

SSH-доступ и структура `~/domains/<домен>/public_html` — как в v1
(см. `git log` до `v2 reset`, если нужны детали восстановления доступа).
